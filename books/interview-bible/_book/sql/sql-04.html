12 Sprint 4 — Window Functions & Interview Finale

12.1 ROW_NUMBER • RANK • DENSE_RANK • LAG • LEAD • OVER()

Welcome to the final SQL sprint.

By now you’ve learned:

  • filtering;
  • aggregation;
  • joins;
  • CTEs;
  • subqueries.

Now you’ll learn the functions that often separate a confident Junior Analyst from someone who only knows basic SQL.

13 Why Window Functions Matter

Imagine this question.

Who are the top three customers in every city?

GROUP BY cannot answer this alone.

Window functions calculate values without destroying individual rows.

Memory Hook.

GROUP BY collapses.

WINDOW looks through.

14 The Window Mental Model

Think of standing inside a moving window.

The table stays.

The calculation changes.

Rows remain visible.

15 OVER()

Every window function uses:

OVER(...)

Think of it as:

Look through this window.

16 Question 33 — ROW_NUMBER()

16.1 Recruiter Psychology

This is one of the most common technical interview questions.

16.2 Business Task

Number every order.

SELECT order_id,
       amount,
       ROW_NUMBER() OVER(ORDER BY amount DESC) AS row_num
FROM orders;

16.3 Explain It (B2)

I sort orders by amount and assign a unique number to each row.

Memory Hook.

ROW_NUMBER never repeats.

17 Visual

Amount ROW_NUMBER
500 1
400 2
300 3

Unique numbering.

18 Question 34 — RANK()

Business Task.

Rank customers by revenue.

SELECT customer_id,
       revenue,
       RANK() OVER(ORDER BY revenue DESC) AS customer_rank
FROM customer_revenue;

Result.

Revenue Rank
500 1
400 2
400 2
300 4

Notice.

Rank skips numbers.

Memory Hook.

RANK leaves gaps.

19 Question 35 — DENSE_RANK()

Same example.

SELECT customer_id,
       revenue,
       DENSE_RANK() OVER(ORDER BY revenue DESC) AS dense_rank
FROM customer_revenue;

Result.

Revenue Dense Rank
500 1
400 2
400 2
300 3

No gaps.

Memory Hook.

Dense fills gaps.

20 Interview Trap

Question.

When would you choose DENSE_RANK instead of RANK?

Good answer.

When tied values shouldn’t create gaps in the ranking.

21 PARTITION BY

Window functions become much more powerful.

Example.

Rank customers inside each city.

SELECT customer_id,
       city,
       revenue,
       ROW_NUMBER()
       OVER(
           PARTITION BY city
           ORDER BY revenue DESC
       ) AS city_rank
FROM customer_revenue;

Memory Hook.

PARTITION creates mini competitions.

22 Visual

250 2

Separate rankings.

23 Question 36 — Top Customer in Every City

Business Task.

Return only the best customer from each city.

WITH ranked AS
(
SELECT customer_id,
       city,
       revenue,
       ROW_NUMBER()
       OVER(
         PARTITION BY city
         ORDER BY revenue DESC
       ) AS rn
FROM customer_revenue
)

SELECT *
FROM ranked
WHERE rn=1;

Explain.

First I rank customers inside each city, then I keep only rank one.

24 LAG()

LAG compares with the previous row.

Business Task.

Compare today’s revenue with yesterday’s.

SELECT order_date,
       revenue,
       LAG(revenue)
       OVER(ORDER BY order_date) AS previous_day
FROM daily_sales;

Memory Hook.

LAG looks back.

25 LEAD()

LEAD looks forward.

SELECT order_date,
       revenue,
       LEAD(revenue)
       OVER(ORDER BY order_date) AS next_day
FROM daily_sales;

Memory Hook.

LEAD looks ahead.

26 Running Total

A classic interview question.

Business Task.

Calculate cumulative revenue.

SELECT order_date,
       amount,
       SUM(amount)
       OVER(
         ORDER BY order_date
       ) AS running_total
FROM orders;

Explain.

The total grows after every row.

Memory Hook.

Running total keeps growing.

27 Moving Average

Another popular interview task.

SELECT order_date,
       revenue,
       AVG(revenue)
       OVER(
         ORDER BY order_date
         ROWS BETWEEN 6 PRECEDING
         AND CURRENT ROW
       ) AS seven_day_average
FROM daily_sales;

Interview Tip.

Don’t memorise.

Understand.

The window moves.

28 Window Function Cheat Sheet

Function Purpose
ROW_NUMBER Unique numbering
RANK Ranking with gaps
DENSE_RANK Ranking without gaps
LAG Previous row
LEAD Next row
SUM OVER Running total

29 Business Case 1 — Tesco

Question.

Which city generated the most revenue?

Expected Thinking.

  • Join customers.
  • Group by city.
  • Sum revenue.
  • Sort descending.

Expected Solution.

Use:

  • ROW_NUMBER
  • PARTITION BY

31 Business Case 3 — Deliveroo

Question.

Find customers who haven’t ordered recently.

Expected Thinking.

  • Latest order.
  • Compare dates.
  • Filter inactive customers.

32 Business Case 4 — NHS

Calculate average appointments per patient.

Business changes.

Logic stays.

Expected Thinking.

40 Interview English Cheat Sheet

Useful phrases.

Instead of:

“SQL does this…”

Say:

First I filter…

Then I group…

After that I calculate…

Finally I sort…

This sounds much more natural in interviews.
