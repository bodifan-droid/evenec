15 Question 26 — INNER JOIN

15.1 Recruiter Psychology

This is one of the most common interview questions.

15.2 Business Task

Show every order together with the customer’s name.

15.3 SQL Solution

SELECT c.first_name,
       o.order_id,
       o.amount
FROM customers c
INNER JOIN orders o
ON c.customer_id = o.customer_id;

15.4 Explain It (B2)

I connect customers and orders using customer_id and return customer names with their orders.

15.5 Memory Hook

INNER = Both must exist.

16 INNER JOIN Visual

Only the overlap remains.

17 Question 27 — LEFT JOIN

17.1 Business Task

Show every customer, even if they never ordered.

17.2 SQL

SELECT c.first_name,
       o.order_id
FROM customers c
LEFT JOIN orders o
ON c.customer_id = o.customer_id;

17.3 Explain It (B2)

Every customer appears. Missing orders become NULL.

17.4 Memory Hook

Left keeps everyone.

This phrase will appear throughout the book.

18 LEFT JOIN Visual

Everything from the left table survives.

19 Interview Trap

Question.

Why is LEFT JOIN useful?

Good answer.

It allows me to keep every customer even when related records don’t exist.

Avoid saying.

Because it joins left.

Explain the business value.

20 Question 28 — Find Customers Without Orders

20.1 SQL

SELECT c.first_name
FROM customers c
LEFT JOIN orders o
ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;

20.2 Explain It (B2)

I keep every customer and filter those without matching orders.

Memory Hook.

NULL means “missing”.

21 Question 29 — Join Three Tables

Business questions often need multiple joins.

Example.

Customers.

Orders.

Payments.

SELECT c.first_name,
       o.order_id,
       p.payment_method
FROM customers c
JOIN orders o
ON c.customer_id = o.customer_id
JOIN payments p
ON o.order_id = p.order_id;

Explain.

First I connect customers to orders, then orders to payments.

Think.

Step by step.

23 CTE — Common Table Expression

Interviewers love CTEs because they improve readability.

Memory Hook.

CTE = Temporary workspace.

Instead of writing one giant query,

build it in steps.

24 Question 30 — First CTE

Business Task.

Find high-value customers.

WITH customer_revenue AS (
    SELECT customer_id,
           SUM(amount) AS revenue
    FROM orders
    GROUP BY customer_id
)
SELECT *
FROM customer_revenue
WHERE revenue > 500;

24.1 Explain It (B2)

First I create a temporary table, then I filter it.

Memory Hook.

WITH creates a temporary workspace.

25 Why CTE Is Better

Instead of.

SELECT ...

inside another huge query,

split the problem.

Cleaner.

Easier to explain.

Interviewers appreciate readability.

26 Subqueries

A subquery is simply

a query inside another query.

Memory Hook.

Box inside a box.

27 Question 31 — Above Average Orders

Business Task.

Find orders larger than the average.

SELECT order_id,
       amount
FROM orders
WHERE amount >
(
    SELECT AVG(amount)
    FROM orders
);

27.1 Explain It (B2)

First SQL calculates the average, then it compares every order against it.

28 Subquery Visual

Main Query

AVG(amount)

One query feeds another.

29 Question 32 — Products Above Average Price

SELECT product_name,
       price
FROM products
WHERE price >
(
    SELECT AVG(price)
    FROM products
);

Explain.

Products become filtered using the average price.

30 CTE vs Subquery

CTE Subquery
Easier to read Shorter
Reusable Quick calculations
Better for interviews Fine for simple tasks

Interview Tip.

If readability matters,

choose a CTE.

31 Business Case — Amazon Style

Imagine this question.

Find customers whose spending is above the company average.

Think aloud.

  1. Calculate customer revenue.
  2. Calculate average revenue.
  3. Compare.

Interviewers score your reasoning,

not just the final SQL.
